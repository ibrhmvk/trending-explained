How Kimi K3 serves 2.8 trillion parameters by waking up only 104 billion

The first open 3T-class model

Kimi K3 is Moonshot AI's new flagship: a 2.8-trillion-parameter, natively multimodal model with a 1,048,576-token context window, and — the part driving the GitHub stars — fully released weights under the Kimi K3 License. The repo itself is just a README, a license, and a tech report PDF; the weights live on Hugging Face. But that README is doing a lot of work: it publishes a benchmark table where an open model trades blows with Claude Opus 4.8, GPT-5.5, and the newest frontier releases on coding and agentic benchmarks. Open releases have flirted with the 1T mark before; nobody has published weights at 2.8T. That is the news.

How a 2.8T model stays runnable

The headline number is misleading in a useful way: only about 104B parameters activate per token, roughly 3.7% of the model. K3's feed-forward layers are split into 896 experts, and a router selects 16 of them per token (plus 2 shared experts that always run) under what Moonshot calls a Stable LatentMoE framework. They claim this scaled-up sparsity yields about 2.5× better scaling efficiency than Kimi K2.

The attention stack is the other half of the story. Of the 93 layers, 69 use Kimi Delta Attention (KDA), a linear-attention variant whose cost doesn't explode with sequence length — that's what makes a million-token context economically sane. The remaining 24 layers keep full gated MLA attention for exact long-range recall, with a new Attention Residuals (AttnRes) mechanism carrying information across the stack. It's a pragmatic hybrid: cheap approximate attention almost everywhere, exact attention where it counts.

Deployment-wise, quantization isn't an afterthought. K3 was trained with quantization-aware training from the SFT stage onward, using MXFP4 weights and MXFP8 activations — so the released 4-bit weights are what the training loop actually optimized, not a lossy post-hoc compression. At 4 bits, 2.8T parameters is roughly 1.4TB of weights instead of 5.6TB. It runs on vLLM, SGLang, and TokenSpeed.

The interesting detail: the model remembers what it didn't say

K3 always thinks (reasoning is non-optional; you tune it with a reasoning_effort field of low/high/max), and it was trained in what Moonshot calls preserved thinking history mode. Most reasoning models discard their chain of thought between turns. K3 requires the opposite: you must pass the assistant's reasoning_content back in messages exactly as the API returned it. The README demonstrates why with a neat example:

messages = [
    {"role": "user", "content": "Tell me three random numbers."},
    {
        "role": "assistant",
        "reasoning_content": "I'll start by listing five numbers: 473, 921, 235, 215, 222, and I'll tell you the first three.",
        "content": "473, 921, 235"
    },
    {"role": "user", "content": "What are the other two numbers you have in mind?"}
]

response = client.chat.completions.create(
    model="kimi-k3", messages=messages, reasoning_effort="max"
)
# the assistant should mention 215 and 222 from the prior reasoning

The model privately thought of five numbers, said three, and can later recall the other two — because its own past reasoning is still in context. For long agentic sessions this is significant: the model's working memory spans turns and tool calls instead of resetting at each visible message. It also means client code that "helpfully" strips reasoning fields before resending history will quietly lobotomize the model mid-task.

Who should use it

  • API users: it's kimi-k3 on platform.kimi.ai, with OpenAI- and Anthropic-compatible endpoints. Moonshot pitches Kimi Code CLI as the intended agent harness.
  • Self-hosters: real weights, real inference-engine support — but 104B active parameters means a multi-GPU cluster, not a workstation. This is open, not lightweight.
  • Researchers: the first inspectable artifact of 3T-class training: hybrid KDA/MLA attention, 16-of-896 expert sparsity, and native MXFP4 QAT, with a tech report in the repo.

Even if you never run it, K3 is worth reading as a statement of where frontier architecture is heading: sparser experts, mostly-linear attention, low-precision training from the start, and reasoning treated as persistent state rather than disposable scratch work.
